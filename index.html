⚠️ Failure Scenarios & Recovery

Scenario 1: LLM Timeout

Problem

GPT-4 API doesn't respond within 30 seconds

Recovery
  1. Check Redis cache for similar message
  2. Fall back to GPT-3.5 (faster)
  3. Use template-based response
  4. Queue for human review

Scenario 2: CRM API Down

Problem

HubSpot returns 503 Service Unavailable

Recovery
  1. Retry with exponential backoff (1,2,4,8,16s)
  2. Max 5 attempts, then queue to DLQ
  3. Alert ops team
  4. Auto-retry after 1 hour

Scenario 3: DB Connection Pool Exhausted

Problem

PostgreSQL connection pool at max (100/100)

Recovery
  1. Kill idle connections (>30 min)
  2. Route queries to read replica
  3. Temporarily increase pool size
  4. Auto-scale infrastructure

Scenario 4: Social Media Webhook Down

Problem

Meta Graph API webhook fails, messages not delivered

Recovery
  1. Automatic fallback to polling (5-min interval)
  2. Fetch missed messages retroactively
  3. Persist to message queue
  4. Process in correct order

Resilience Guarantees

RTO (Recovery Time Objective)

Most issues: < 5 minutes | Critical: < 1 minute

RPO (Recovery Point Objective)

Zero data loss (persistent queues + backups)

Uptime SLA

99.95% (21.9 min/month max downtime)

Circuit Breaker

Open after 5 failures, retry after 60s
